# 회의록 정리 (meeting-summarize)

녹음 파일 하나(또는 이미 만들어진 녹취록 txt)에서 **녹취록 txt와 XBridge 내부용 8항목 회의록 md** 두 산출물을 만든다. 흐름: `녹음 → 녹취록 전환(scripts/transcribe.sh, 완전 로컬) → 회의록 요약`. 원칙 넷: **우리 관점**으로 쓴다(6·7·8번은 "우리가 무엇을 할 것인가"), **상대의 이야기는 스토리까지** 남긴다(대외 미팅 5-1 필수), **Follow-Up은 상대가 기다리는 약속만** 넣는다(나머지는 6번 내부 참고), **요약본이다** — 녹취는 별도 공유하고 회의록에는 주요 항목·논의 결론·액션만 담으며 저장 전에 검증 패스를 거친다.

`<스킬 폴더>` = 이 파일이 있는 폴더. 항목별 형식·규칙은 `references/template.md`, 우리 측 정보는 `references/context.md`, 리뷰에서 배운 규칙은 `references/feedback.md`, 완성 예시는 `references/example.md`(형식·문체·수치 표기의 기준일 뿐, 그 내용은 이번 회의의 근거가 아니다 — 같은 상대와의 다음 회의에서도 예시의 사실을 옮겨 적지 않는다). **초안을 쓰기 전에 template.md·context.md·feedback.md를 읽는다.**

## 절차

1. **입력 확인**: `python3 <스킬 폴더>/scripts/transcripts.py list [폴더]`. 기본 폴더는 iCloud 회의록 폴더(`~/Library/Mobile Documents/iCloud~is~workflow~my~workflows/Documents/회의록`, 스크립트에 내장). 사용자가 미팅명·날짜를 말했으면 그 파일을 고르고, 아니면 표를 보여주고 고르게 한다. 표 아래 "녹취록이 없는 녹음"에 있거나 사용자가 녹음 파일을 줬으면 **1-a 녹취록 전환**으로 간다.
   - **1-a. 녹취록 전환** (녹음만 있을 때): 먼저 사용자에게 **녹음 시작 시각**(m4a에는 없다)과 **참석자 수**를 묻는다 — 이미 대화에 있으면 묻지 않고, 모른다고 하면 시각은 추정·참석자 수는 자동으로 둔다. 그다음 `bash <스킬 폴더>/scripts/transcribe.sh "<녹음 파일>" --start "YYYY-MM-DD HH:MM" --speakers N --author <녹음자>`를 돌린다(`--author` 기본은 context.md의 작성자, 보통 차동훈). 같은 폴더에 `{녹음명}.txt`가 생기며 이후 절차는 이 파일로 진행한다. 78분 녹음에 5~10분 걸리고, 첫 실행은 모델 약 1.7GB를 내려받는다 — 실행 전에 이 둘을 알린다. `ffmpeg`·`whisperkit-cli`가 없으면 스크립트가 `brew install ffmpeg whisperkit-cli`를 안내하고 멈춘다(설치는 사용자가 한다). 같은 이름의 txt가 이미 있으면 덮어쓰지 않고 멈춘다 — 사용자 확인 후 `--force` 또는 `--out`. 이렇게 만든 녹취록은 **자체 전사본**이다: 정답지 대조 실측(2026-09-07)에서 화자 라벨은 상용 앱 수준(일치율 0.94)이지만 고유명사·숫자는 글자 100자 중 16~17자가 달랐다. 확인 게이트와 검증 패스에서 아래 표시를 따른다.
2. **메타 추출**: `python3 <스킬 폴더>/scripts/transcripts.py meta <파일>`(`list`가 보여 준 파일명만 넘겨도 기본 폴더에서 찾는다. 다른 폴더면 절대 경로). 1번 일시 문자열·작성자·화자별 발화량이 나온다. 일시는 이 출력을 **그대로** 쓴다(직접 계산·재표기하지 않는다).
3. **전문 읽기**: 파일을 **끝까지** 읽는다(60~110KB). Read 툴로 300행씩 나눠 읽는다 — `sed`/`cat` 출력은 잘려서 파일로 빠지므로 쓰지 않는다. 생략 금지. 미팅 초반 20~30분의 잡담·개인사가 5-1의 원천이므로 초반을 건너뛰지 않는다. 읽으면서 (a) 화자별 단서, (b) 수치·가격·기간, (c) "하겠다/보내겠다/회신하겠다" 발언, (d) 상대가 원칙·컨셉을 들어 거리를 둔 제안, (e) 제3자가 이름·직함으로 지목한 발언(F-03)을 메모한다. **회의 유형**을 정한다: 발화량 상위 화자가 모두 context.md 구성원이면 내부 회의(template.md "회의 유형"의 내부 모드 — 5-1은 배경·목적, 6번은 결정/보류/전제), 상대 조직이 있으면 대외 미팅. 후반부에 두 대화가 한 줄씩 교차하는 구간(병렬 대화)이 있으면 그 구간은 발언 주체를 단정하지 않고 사실만 적으며, 확인 게이트에 "○○분 이후 화자 라벨 신뢰도 낮음"을 표시한다.
4. **확인 게이트**: 다음 표를 사용자에게 보여주고 확인받은 뒤 초안으로 간다.
   - 화자 매핑: `참석자 N` → 이름/소속/역할 + 근거(호칭·발화 내용·context.md 단서). 발화량 상위 화자 중 확신이 없는 게 있으면 그렇다고 표시한다. 지목 발언이 직함뿐이고 같은 직함자가 둘이면("우리 실장님") 업무 단서로 가른다 — 개발·시연·플랫폼 설명은 차동훈, 인증·절차·비용 정책·시장 리포트는 홍윤택 — 그리고 두 행 모두 "(확인 필요)"를 붙인다. 발화 1~2회 화자는 "단발 발화(참석대상 제외)". 발화 수는 많지만 짧은 추임새·시식 감상뿐이고 양측 발화가 섞여 보이는 라벨은 "화자 분리 오류 의심 — 실제 동석자인지 확인 요청"으로 표시한다(실제 동석자면 참석대상에 넣고 context.md 갱신을 제안).
   - 장소: 녹취·파일명에 근거가 있으면 그것, 없으면 "미확인 — 알려 주시면 넣겠습니다".
   - 자체 전사본이면 두 줄을 덧붙인다: ① 일시 — `meta` 출력에 "(시작 시각 추정 — 확인 필요)"가 있으면 시각을 확인받고, 확인 못 받으면 회의록 1번에 "(추정)"을 남긴다. ② "자체 전사본 — 고유명사·금액·수량은 오인식 가능성이 높아 5·7번의 수치와 이름은 검증 패스에서 원문 대조 후 확인 필요 표시가 붙을 수 있음".
   사용자가 이미 대화에서 알려 준 정보가 있으면 그것을 쓰고 이 단계는 결과 통보로 줄인다. 확인을 받지 못한 채 진행해야 하면 3번 표의 해당 행과 2번 장소에 "(확인 필요)"를 붙여 문서 자체에 남긴다.
5. **초안**: template.md의 항목 순서·표 형식대로 쓴다. **대외 미팅이면 5-1 스토리텔링 슬롯을 먼저 채운다**(훅 중심 5불릿). **분량 예산**(template.md)을 지킨다 — 불릿은 "결론 + 핵심 근거 하나", 발언 흐름·인용·근거 나열 금지. 초안을 스크래치패드에 쓰고 `python3 <스킬 폴더>/scripts/transcripts.py check <초안>`을 돌려 위반 0건이 될 때까지 줄인다. 수치·가격·기간·고유명사는 원문 그대로(반올림·환산 금지, 단위 유지). 5번 각 줄에 누구 말인지(대표 의견 / {이름} 제안 / 합의)를 밝힌다. 오인식이 의심되는 고유명사는 "(녹취 표기 그대로)" 또는 "(녹취상 불명확)"을 붙이고, 어느 제품·항목의 수치인지 추론으로 배치한 값은 "(확인 필요)"를 붙인다.
6. **Follow-Up 필터**: 7번 초안의 행마다 두 질문 — (a) 녹취에서 누군가 그 일을 "하겠다"고 말했는가, (b) 상대가 그 결과를 기다리고 있고 상대의 원칙과 충돌하지 않는가. 둘 다 예 → 7번에 남긴다. (a)만 예 → 6번 "내부 참고 (지금은 상대에게 꺼내지 않음)"으로 옮기고 다시 꺼낼 조건을 적는다. 상대의 자체 계획(패키지 리뉴얼·인증 재도전·신제품 개발)은 7번이 아니라 5번 현황에 둔다. 우리 내부 일정(자사몰 오픈 등)은 6번에 둔다. 상대측 담당 행은 상대가 "하겠다"고 말한 것만 넣는다 — 우리가 요청했지만 상대의 수락 발언이 없으면 7번이 아니라 6번 선행 과제에 "요청 예정"으로 적는다. **내부 회의**에서는 두 질문을 (a) 누군가 "하겠다"고 했거나 대표가 지시했는가, (b) 담당과 기한(또는 다음 회의)이 정해졌는가로 바꾼다. 보류·철회·"다음에 다시 보자"는 6번 보류·이견에 둔다.
7. **피드백 로그 대조**: feedback.md의 모든 `F-NN` "적용 체크"를 초안에 대조한다. 하나라도 걸리면 고친다.
8. **검증 패스** (F-05 — "다시 한번 검증해서 올려 주세요"):
   - (a) 작성자 체크: ① 수치·금액·날짜·기한·단위가 녹취와 같은가(자체 전사본이면 녹취 자체가 틀릴 수 있다 — 같은 값이 녹취 안에서 두 가지로 나오면 둘 다 적고 "(확인 필요)", 고유명사 표기가 갈리면 context.md 표기로 통일하되 "(녹취 표기 상이)") ② 각 불릿의 발언 주체가 맞는가(F-03 지목 발언 목록과 3번 표 대조) ③ "합의"로 쓴 것이 실제 합의인가(의견·아이디어와 구분) ④ 7번 각 행의 담당·기한이 녹취 발언에 있는가 ⑤ 고유명사·STT 오인식 표기 ⑥ 5번과 6·7·8번 사이 모순 ⑦ 녹취를 10분 구간으로 나눠 각 구간의 핵심 주제가 회의록 어디에 있는지 — 없으면 누락 ⑧ 내부용이라도 부적절한 표현(개인 건강·인사 평가·상대 험담) ⑨ `check` 위반 0건.
   - (b) 독립 검증: Agent 툴로 검증자 서브에이전트 하나를 보낸다. 입력은 녹취록 경로·초안 경로·검증 목록(모든 수치, 7번 전 행, "합의" 표시 전부, 화자 지목 발언, 10분 구간 커버리지). 출력은 표 `항목 | 초안 표기 | 녹취 근거(MM:SS) | 판정(일치/불일치/근거 없음)`과 누락 주제 목록. 누락은 **결정·액션·수치·리스크에 영향을 주는 주제**만 센다(잡담·반복 발언·부연은 누락이 아니다). 검증자는 초안을 고치지 않고 판정만 한다. 수치·고유명사 대조는 녹취 전체를 다시 읽기보다 `grep -n`으로 찾게 하면 빠르다.
   - (c) 불일치는 고치고, 근거 없음은 "(확인 필요)"로 바꾼다. 고친 항목이 수치·Follow-Up이면 그 항목만 다시 대조한다.
   - (d) 검증 메모를 만든다: 대조 N건 · 수정 M건 · 확인 필요 K건(목록) · 분량 예산 때문에 요약에서 뺀 주제 J건(제목만 나열, "녹취 참조"). 회의록 본문이 아니라 사용자 보고에 넣는다. 뺀 주제 중 결정·액션·수치·리스크에 닿는 것이 있으면 예산 안의 다른 불릿과 바꿔 넣는다.
9. **저장·전달**: 원본과 같은 폴더에 `{원본 파일명(확장자 제외)}_회의록.md`로 저장한다. 같은 이름이 있으면 덮어쓰지 않고 `_회의록_v2.md`, `_v3.md`. 사용자에게 **두 산출물의 경로**(녹취록 txt — 1-a에서 만들었으면 — 와 회의록 md), 검증 메모, "(확인 필요)" 항목 목록을 알린 뒤 **회의록 전문을 대화에 출력**한다(복사해 전달하는 용도). 녹취 전문은 회의록에 넣지 않고 녹취록 파일명을 알려 별도 공유하게 한다.

## 피드백을 받았을 때

사용자가 정리된 회의록에 대한 리뷰(상사·동료 코멘트)를 붙여 주면:

1. 지적을 반영해 해당 회의록을 고치고 `_v2`로 저장한다(원본 정리본은 남긴다).
2. 지적을 **이 회의에만 해당하는 수정**과 **다음에도 적용할 규칙**으로 나눈다. 규칙은 feedback.md 맨 아래에 `F-NN · 날짜 · 출처` 형식(피드백 요지 → 규칙 → 적용 체크)으로 추가한다. 항목 구조가 바뀌면 template.md도 같이 고친다. **규칙 파일은 소스 저장소에 쓴다**: `/Users/joseph.c/Work/Samples/skills/meeting-summarize/skills/meeting-summarize/references/`. 지금 읽고 있는 스킬 폴더가 `~/.claude/plugins/cache/` 아래면 거기는 플러그인 업데이트 때 덮어써지므로 쓰지 않는다 — 소스 저장소가 없는 PC면 규칙 텍스트를 보고에 남기고 사용자에게 알린다. 반영본 배포는 사용자가 요청할 때 프로젝트의 `release-plugin` 스킬로 한다.
3. 어떤 규칙을 추가했는지 사용자에게 보여준다. 피드백에 동의하기 어려운 점이 있으면 규칙으로 굳히기 전에 한 줄로 이유를 말하고 사용자 판단을 따른다.

## 금지

- 녹취에 없는 사실·수치·장소를 만들어 넣기(모르면 "미확인").
- 내부용 문서를 외부 공유용으로 순화하기 — 상대의 약점·리스크(승계·인력·인증 부재)를 그대로 쓴다.
- 파일 전체를 읽지 않고 앞부분만 보고 쓰기.
- 검증 패스 없이 저장하기, `check` 위반이 남은 채 저장하기.
- 사용자 확인 없이 기존 회의록·녹취록 파일 덮어쓰기.
- 녹음 파일을 외부 서비스에 올리기 — 전사는 `transcribe.sh`로 기기 안에서만 한다. Anthropic으로 가는 것은 텍스트뿐이다.
