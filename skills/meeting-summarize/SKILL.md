# 회의록 정리 (meeting-summarize)

녹취록 하나를 읽고 **XBridge 내부용** 8항목 회의록을 쓴다. 원칙 셋: **우리 관점**으로 쓴다(6·7·8번은 "우리가 무엇을 할 것인가"), **상대의 이야기는 스토리까지** 남긴다(5-1 필수), **Follow-Up은 상대가 기다리는 약속만** 넣는다(나머지는 6번 내부 참고).

`<스킬 폴더>` = 이 파일이 있는 폴더. 항목별 형식·규칙은 `references/template.md`, 우리 측 정보는 `references/context.md`, 리뷰에서 배운 규칙은 `references/feedback.md`, 완성 예시는 `references/example.md`(형식·문체·수치 표기의 기준일 뿐, 그 내용은 이번 회의의 근거가 아니다 — 같은 상대와의 다음 회의에서도 예시의 사실을 옮겨 적지 않는다). **초안을 쓰기 전에 template.md·context.md·feedback.md를 읽는다.**

## 절차

1. **입력 확인**: `python3 <스킬 폴더>/scripts/transcripts.py list [폴더]`. 기본 폴더는 iCloud 회의록 폴더(`~/Library/Mobile Documents/iCloud~is~workflow~my~workflows/Documents/회의록`, 스크립트에 내장). 사용자가 미팅명·날짜를 말했으면 그 파일을 고르고, 아니면 표를 보여주고 고르게 한다. 오디오(m4a)만 있는 회의는 녹취록 txt가 필요하다고 안내한다(전사는 이 스킬 범위 밖).
2. **메타 추출**: `python3 <스킬 폴더>/scripts/transcripts.py meta <파일>`(`list`가 보여 준 파일명만 넘겨도 기본 폴더에서 찾는다. 다른 폴더면 절대 경로). 1번 일시 문자열·작성자·화자별 발화량이 나온다. 일시는 이 출력을 **그대로** 쓴다(직접 계산·재표기하지 않는다).
3. **전문 읽기**: 파일을 **끝까지** 읽는다(60~90KB, 나눠 읽더라도 생략 금지). 미팅 초반 20~30분의 잡담·개인사가 5-1의 원천이므로 초반을 건너뛰지 않는다. 읽으면서 (a) 화자별 단서, (b) 수치·가격·기간, (c) "하겠다/보내겠다/회신하겠다" 발언, (d) 상대가 원칙·컨셉을 들어 거리를 둔 제안을 메모한다. 후반부에 두 대화가 한 줄씩 교차하는 구간(병렬 대화)이 있으면 그 구간은 발언 주체를 단정하지 않고 사실만 적으며, 확인 게이트에 "○○분 이후 화자 라벨 신뢰도 낮음"을 표시한다.
4. **확인 게이트**: 다음 표를 사용자에게 보여주고 확인받은 뒤 초안으로 간다.
   - 화자 매핑: `참석자 N` → 이름/소속/역할 + 근거(호칭·발화 내용·context.md 단서). 발화량 상위 화자 중 확신이 없는 게 있으면 그렇다고 표시한다. 발화 1~2회 화자는 "단발 발화(참석대상 제외)". 발화 수는 많지만 짧은 추임새·시식 감상뿐이고 양측 발화가 섞여 보이는 라벨은 "화자 분리 오류 의심 — 실제 동석자인지 확인 요청"으로 표시한다(실제 동석자면 참석대상에 넣고 context.md 갱신을 제안).
   - 장소: 녹취·파일명에 근거가 있으면 그것, 없으면 "미확인 — 알려 주시면 넣겠습니다".
   사용자가 이미 대화에서 알려 준 정보가 있으면 그것을 쓰고 이 단계는 결과 통보로 줄인다. 확인을 받지 못한 채 진행해야 하면 3번 표의 해당 행과 2번 장소에 "(확인 필요)"를 붙여 문서 자체에 남긴다.
5. **초안**: template.md의 항목 순서·표 형식대로 쓴다. **5-1 스토리텔링 슬롯을 먼저 채운다.** 수치·가격·기간·고유명사는 원문 그대로(반올림·환산 금지, 단위 유지). 5번 각 줄에 누구 말인지(대표 의견 / {이름} 제안 / 합의)를 밝힌다. 오인식이 의심되는 고유명사는 "(녹취 표기 그대로)" 또는 "(녹취상 불명확)"을 붙이고, 어느 제품·항목의 수치인지 추론으로 배치한 값은 "(확인 필요)"를 붙인다.
6. **Follow-Up 필터**: 7번 초안의 행마다 두 질문 — (a) 녹취에서 누군가 그 일을 "하겠다"고 말했는가, (b) 상대가 그 결과를 기다리고 있고 상대의 원칙과 충돌하지 않는가. 둘 다 예 → 7번에 남긴다. (a)만 예 → 6번 "내부 참고 (지금은 상대에게 꺼내지 않음)"으로 옮기고 다시 꺼낼 조건을 적는다. 상대의 자체 계획(패키지 리뉴얼·인증 재도전·신제품 개발)은 7번이 아니라 5번 현황에 둔다. 우리 내부 일정(자사몰 오픈 등)은 6번에 둔다.
7. **피드백 로그 대조**: feedback.md의 모든 `F-NN` "적용 체크"를 초안에 대조한다. 하나라도 걸리면 고친다.
8. **저장·전달**: 원본과 같은 폴더에 `{원본 파일명(확장자 제외)}_회의록.md`로 저장한다. 같은 이름이 있으면 덮어쓰지 않고 `_회의록_v2.md`, `_v3.md`. 사용자에게 저장 경로와 "(확인 필요)" 항목 목록을 알린 뒤 **회의록 전문을 대화에 출력**한다(복사해 전달하는 용도).

## 피드백을 받았을 때

사용자가 정리된 회의록에 대한 리뷰(상사·동료 코멘트)를 붙여 주면:

1. 지적을 반영해 해당 회의록을 고치고 `_v2`로 저장한다(원본 정리본은 남긴다).
2. 지적을 **이 회의에만 해당하는 수정**과 **다음에도 적용할 규칙**으로 나눈다. 규칙은 feedback.md 맨 아래에 `F-NN · 날짜 · 출처` 형식(피드백 요지 → 규칙 → 적용 체크)으로 추가한다. 항목 구조가 바뀌면 template.md도 같이 고친다.
3. 어떤 규칙을 추가했는지 사용자에게 보여준다. 피드백에 동의하기 어려운 점이 있으면 규칙으로 굳히기 전에 한 줄로 이유를 말하고 사용자 판단을 따른다.

## 항목별 빠른 참조

| 항목 | 넣는 것 | 넣지 않는 것 |
| --- | --- | --- |
| 1 일시 | `transcripts.py meta`의 "일시:" 줄 그대로 | "오후 1:31", "총 61분 41초" 같은 재표기 |
| 2 장소 | 녹취·파일명·사용자 확인에 근거한 장소 | 추정 지명 |
| 3 참석대상 | 표 하나(구분·참석자·역할), 상대측 먼저, 작성자 표시 | "참석자 2" 라벨, 조직별 표 분리, 단발 화자 |
| 4 주요 안건 | 3~5개 명사구 | 논의된 모든 소재 나열 |
| 5 협의 사항 | 5-1 스토리텔링(필수) → 주제별 소제목, 현황은 표, 발언 주체 표시 | 출처 없는 요약, 반올림한 수치 |
| 6 특이사항 | 우리 관점의 제약·선행 과제·기회·내부 참고·리스크·소통 채널 | 상대를 배려한 순화 |
| 7 Follow-Up | 양측이 서로에게 약속한 것(담당·내용·기한) | 상대 자체 계획, 우리 내부 일정, 보류한 아이디어, "소통 채널" |
| 8 소감 | 개조식 3~5개, 작성자의 판단·전략 | 서술형 문단, 6번 반복, 보류한 아이디어 밀어붙이기 |

## 흔한 실수 (스킬 없이 정리했을 때 실제로 나온 것)

| 실수 | 고치기 |
| --- | --- |
| 대표의 창업기·개발 이야기를 6번 "참고"로 압축하거나 통째로 뺌 — "후속 액션과 직결되지 않아 5번에 넣으면 실무 내용이 묻힌다" | 5-1 소제목에 넣는다. 묻히는 문제는 소제목이 해결한다. 마케팅 스토리는 내부 회의록의 필수 산출물이다 |
| Follow-Up 16행 — 상대의 단상자 제작·패키지 결정·HACCP 재도전·신제품 개발, 우리 자사몰 런칭, "샘플 수령", "메일+전화 병행"까지 | 7번은 서로에게 약속한 것만. 상대 계획은 5번, 우리 일정·소통 채널은 6번 |
| 우리가 던졌지만 상대가 원칙(국산·유기농)을 들어 거리를 둔 아이디어를 "조사 후 회신"으로 7번에 넣고, 소감에서 "설득 가능"이라고 밀어붙임 | F-02. 6번 내부 참고 + 다시 꺼낼 조건. 소감도 보류 결정을 따른다 |
| 일시를 "오후 1:31 ~ 오후 2:33 (총 61분 41초)"로 재표기 | 스크립트 출력 그대로 |
| 참석대상을 "참석자 2"로 두거나 조직별 표 두 개로 쪼갬 | context.md로 이름 매핑, 표 하나 |
| 장소를 "지리산 인근 본사"처럼 추정 | 확인 게이트에서 묻는다 |
| 소감을 서술형 문단 4개로 씀 | 개조식 3~5개 |
| 5번에 발언 주체 없이 사실만 나열 | "대표 의견 / {이름} 제안 / 합의" |

## 금지

- 녹취에 없는 사실·수치·장소를 만들어 넣기(모르면 "미확인").
- 내부용 문서를 외부 공유용으로 순화하기 — 상대의 약점·리스크(승계·인력·인증 부재)를 그대로 쓴다.
- 파일 전체를 읽지 않고 앞부분만 보고 쓰기.
- 사용자 확인 없이 기존 회의록 파일 덮어쓰기.
