# 회의록 템플릿 (8항목)

항목 번호·제목·순서는 고정이다. `{ }`는 채우는 자리, `←`는 규칙. 녹취에 근거가 없는 자리는 지어내지 않고 "미확인(녹취상 언급 없음)"으로 둔다. 문체는 개조식(명사형 종결), 표는 마크다운. **회의록은 요약본이다** — 녹취는 별도 공유하고, 여기에는 주요 항목·논의 결론·액션만 담는다(분량 예산은 아래).

## 분량 예산 (F-04)

| 항목 | 상한 | 비고 |
| --- | --- | --- |
| 전체 | 약 60~80줄, 공백 제외 3,500자 | `transcripts.py check`가 잰다 |
| 3 참석대상 | 표 1개, 6행 | |
| 4 주요 안건 | 3~5개 | |
| 5-1 스토리텔링(대외 미팅) | 불릿 5개, 각 1~2문장 | 마케팅 훅만. 에피소드 전문은 녹취 참조 |
| 5-N 안건별 | 불릿 3~5개, 각 1~2문장(120자) | "결론 + 핵심 근거 하나". 발언 흐름·인용 금지 |
| 표 | 문서 전체 2개, 각 8행 | 참석대상 표는 제외 |
| 6 특이사항 | 불릿 6개 | |
| 7 Follow-Up | 8행 | |
| 8 소감 | 불릿 3~4개, 각 1문장 | |

녹취 말투("~거든요", "~잖아요", "그러니까", "이제", "약간")가 남아 있으면 녹취를 그대로 옮긴 것이다 — 결론형 명사구로 다시 쓴다. 상세가 정말 필요하면 사용자 요청 시에만 `_회의록_상세.md`를 따로 만든다(본문 예산은 그대로).

## 회의 유형

- **대외 미팅**(상대 조직이 있음): 아래 템플릿 그대로. 5-1 스토리텔링 필수.
- **내부 회의**(주요 화자가 모두 context.md 구성원): 제목은 `회의록 — XBridge {회의명}`. 3번은 우리 측만. **5-1은 "배경·목적"**(1~3불릿, 없으면 생략)으로 바꾼다. 회의에서 브랜드 스토리 재료(창업 계기·체험담·에피소드)가 나왔으면 같은 5-1에 **"스토리 재료" 1~2불릿**을 덧붙인다 — 대표의 그라운드 룰("스토리텔링은 회의록에 담아라")과 F-01을 내부 회의에도 최소 단위로 적용하는 것이다. 5-2~5-N은 **안건별 논의 요지**: 쟁점 → 의견(이름) → 결론 또는 보류. 6번 불릿은 **결정 사항 / 보류·이견 / 전제·리스크 / 다음 회의 준비**로 둔다. 7번은 액션 아이템(담당·기한). 8번 소감은 그대로. 화자 매핑은 feedback.md F-03의 우선순위를 따른다(대외 프로필로 발표자를 단정하지 않는다).

```markdown
# 회의록 — {상대 조직명} {미팅 성격: 방문 미팅 / 화상 미팅 / 상담}

> 녹취록: {원본 파일명} (전문 별도 공유) · 작성: {작성자} · 검증: {검증 패스 일자}

## 1. 일시

* {YYYY년 M월 D일(요일) HH:MM ~ HH:MM (약 N분)}
```
← `scripts/transcripts.py meta` 출력의 "일시:" 줄을 그대로 붙인다(직접 계산하지 않는다). 자체 전사본(`transcribe.sh`)에서 시작 시각을 추정했으면 출력에 "(시작 시각 추정 — 확인 필요)"가 붙는다 — 사용자 확인을 받으면 그 시각으로 고쳐 쓰고, 못 받으면 "(추정)"만 남긴다.

```markdown
## 2. 장소

* {상대 사무실/공장/매장 등 + 지역(시·군)}
```
← 녹취 발화("여기 공장이…", 지명)·파일명·context.md·사용자 확인에 근거가 있을 때만. 없으면 "미확인(녹취상 언급 없음)". 정황 단서(주변 지명 언급)만 있으면 단정하지 말고 단서를 괄호로 남긴다.

```markdown
## 3. 참석대상

| 구분 | 참석자 | 역할 |
| --- | --- | --- |
| {상대 조직} | {직함 또는 이름} | {이 미팅에서의 역할 + 배경 한 줄} |
| {우리 조직} | {이름 직함} | {이 미팅에서의 역할} |
| {우리 조직} | {이름 직함} | {…} (본 회의록 작성) |
```
← 상대측 행이 먼저. 이름을 모르면 직함만("대표"). 경력·배경은 녹취나 context.md에 있을 때만. 발화 1~2회의 단발 화자(자리를 스쳐 간 직원 등)는 넣지 않는다. 상대 조직이 둘 이상이면(예: 물류사 + 관세사무소) 문서 제목에 "A · B"로 병기하고, 3번 표는 상대 조직들 → 우리 순으로, 7번 담당은 "조직(이름)" 형식을 그대로 쓴다.

```markdown
## 4. 주요 안건

1. {안건}  ← 3~5개, 명사구, 미팅 목적 순(상대 파악 → 본건 제안 → 부수 안건)
```

```markdown
## 5. 협의 사항

### 5-1. {상대} 소개 · 스토리텔링

* **배경·이력**: {출신·전공·이전 직업}
* **창업/전환 계기**: {왜 이 일을 시작했나}
* **제품 탄생 에피소드**: {제품별로 "무엇 때문에 → 어떻게 만들었고 → 어떤 반응"}
* **개발 근거·기간**: {논문·해외 자료·조언자·시행착오·소요 기간}
* **철학·고집**: {전통 공법, 원산지, 특허 미등록, 이름을 안 바꾼 이유 등}
* **고객 후기·반응**: {구체 사례 1~3개, 표현을 살려서. 건강 효능은 "후기(고객 주장)"로 표기}
* **실패담·교훈**: {있으면}
```
← **필수 소제목.** 미팅 초반 30분의 잡담·개인사가 원천이다. 마케팅 스토리로 재사용할 수 있게 사실·수치·고유명사·연도를 녹취 그대로 남긴다. 녹취에 없는 줄은 지운다(빈 줄을 남기지 않는다). 상대가 조직(협동조합·기관)이면 "설립 배경·연혁·대표 인물 이야기"로 같은 슬롯을 채운다. 상대가 제조사가 아닌 서비스 제공자(관세사·물류사·컨설팅)면 "상대 조직·담당자 이력 + 우리 제품·사업 스토리에 대한 상대의 반응(시식·평가)"으로 채운다 — 우리 제품 이야기를 우리가 어떻게 말했고 상대가 어떻게 받았는지가 마케팅 재료다.

```markdown
### 5-2. {주제 A: 예 — 제품·사업 현황}

| 제품/항목 | 특징 | 가격 | 생산 방식 / 캐파 |
| --- | --- | --- | --- |
```
← 현황성 정보는 표. 열은 회의에 맞게 바꾼다(가격이 안 나온 회의면 특징/캐파·리드타임/비고 등). 가격·캐파·유통기한·인증·인력·판매 채널은 녹취 수치 그대로(단위 유지, 반올림·환산 금지). 단위가 빠진 수치는 그대로 적고 "(단위는 녹취상 불명확)"을 붙인다.

```markdown
### 5-3. {주제 B: 예 — 본건 협의(수출/제휴)}

* 상대 의견: {…}
* 우리 제안: {…}
* **합의**: {…}  ← 합의된 것만 굵게
```
← 주제 하나에 소제목 하나(5-2 ~ 5-N). 각 줄에 "누구 의견인지"(대표 의견 / {이름} 제안 / 합의)를 밝힌다. 우리가 제안했고 상대가 원칙을 들어 소극적이었던 항목은 여기서 사실대로 적되 "→ 내부 참고(6번)"로 끝맺는다. 불릿은 "결론 + 핵심 근거 하나"다 — 누가 어떤 순서로 무슨 말을 했는지(발언 흐름), 같은 취지의 발언 반복, 근거 수치 나열은 넣지 않는다. 논의 과정이 궁금한 사람은 녹취를 본다. 발표자의 경험치·추정 수치는 확인된 수치와 구분해 "(추정)"을 붙인다. 합의된 것만 "합의"로 쓰고, 의견이 갈린 채 끝났으면 "정리(합의 아님)"로 쓴다.

```markdown
## 6. 특이사항 또는 참고사항 (우리에게 해당되는 사항)

* **핵심 제약**: {캐파·인증·인력 등 우리 제안의 전제를 바꾸는 것}
* **선행 과제**: {우리가 먼저 해야 진행되는 것}
* **기회·확장**: {협업 범위가 넓어질 수 있는 단서}
* **우리 다른 사업과의 연결**: {context.md의 사업과 닿는 이야기}
* **내부 참고 (지금은 상대에게 꺼내지 않음)**: {우리가 던진 아이디어 중 상대의 원칙·컨셉과 충돌하는 것 — 무엇을, 왜 보류하고, 어떤 조건이 되면 다시 꺼낼지}
* **리스크**: {승계·인력·자금·의존도}
* **소통 채널**: {메일/전화/카톡}
```
← "우리에게 해당" = 우리 조직 관점. 내부 문서이므로 상대의 약점·리스크를 순화하지 않는다.

```markdown
## 7. 향후 Follow-Up 및 일정

| 구분 | 담당 | 내용 | 기한 |
| --- | --- | --- | --- |
| {할 일} | {조직(이름)} | {구체 산출물} | {말한 기한 / 미정 / "{선행 항목} 후"} |
```
← 행마다 두 질문에 모두 "예"일 때만 남긴다: (a) 녹취에서 누군가 "하겠다/보내겠다/회신하겠다"고 말했는가, (b) 상대가 그 결과를 기다리고 있고 상대의 원칙과 충돌하지 않는가. (a)만 예이면 6번 "내부 참고"로 옮긴다. 담당은 "XBridge(이름)"처럼 조직(이름). 상대측 행도 넣는다(예: 출하가 제시).

```markdown
## 8. 소감

* {판단 1: 현실적인 전략은 무엇인가}
* {판단 2: 병목과 대안}
* {판단 3: 협업 범위·관계}
* {판단 4: 리스크와 대비}
* {판단 5: 우리의 첫 과제}
```
← 3~4개. 작성자 시각의 "그래서 우리는 이렇게 간다". 6번 항목을 문장만 바꿔 반복하지 않는다.

## 파일명·저장

* 저장 위치: 원본 녹취록과 같은 폴더.
* 파일명: `{원본 파일명(확장자 제외)}_회의록.md`. 이미 있으면 덮어쓰지 않고 `_회의록_v2.md`, `_v3.md`. 원본 파일명이 `TalkFile_`로 시작하거나 잘려 있으면(내보내기 도구가 제목을 자르는 경우가 있다) 대신 헤더 1행의 제목에서 `.m4a`를 뗀 것을 쓴다. 녹음에서 전환한 경우 녹취록은 `{녹음명}.txt`, 회의록은 `{녹음명}_회의록.md`로 나란히 놓인다.
* 문서 제목(첫 줄 `#`)은 "회의록 — {상대} {미팅 성격}".
